# Вопросы пользователя и элементы дашборда

Пользователь: риск-менеджер или трейдер небольшого фонда. Решения: какой объём можно исполнить завтра и нужно ли снижать риск.
Правило из методички: элемент без вопроса удаляется. Каждая строка ниже — элемент файла `cryptocast/dashboard/app.py`.

| Вкладка | Элемент | Вопрос пользователя | Решение, которое он поддерживает |
|---|---|---|---|
| Боковая панель | Инструмент, показатель, период | По какому активу и за какой срок я смотрю данные? | Фокус анализа |
| Боковая панель | Последняя свеча, последний запуск | Насколько свежи эти цифры? | Доверять ли показаниям сегодня |
| Решение на завтра | Ожидаемый объём и диапазон 80% | Какой объём торгов ждать завтра? | Масштаб заявки |
| Решение на завтра | Условная ёмкость исполнения | Сколько можно исполнить, не становясь заметной долей рынка? | Лимит заявки |
| Решение на завтра | Ожидаемая волатильность и диапазон | Насколько сильно может двигаться цена завтра? | Размер позиции, стопы |
| Решение на завтра | Уровень риска | Нужно ли снижать риск? | Снизить экспозицию или нет |
| Решение на завтра | Таблица инструментов | Где завтра риск и ёмкость лучше? | Распределение между активами |
| Факт и прогноз | График факта и прогноза | Как прогноз вёл себя на этом активе раньше? | Доверие к прогнозу |
| Факт и прогноз | Ошибка за 14 дней | Насколько модель ошибается сейчас? | Поправка на ошибку |
| Качество моделей | Таблица моделей | Какая модель лучше и в чём измерена ошибка? | Выбор основы для решения |
| Качество моделей | Столбцы по инструментам | Для каких активов модели дают выигрыш над простым правилом, а для каких нет? | На каких активах полагаться на прогноз |
| Качество моделей | Текстовый вывод | Какой итог сравнения? | Быстрый ответ |
| Объяснение | Вклады признаков для даты | Почему модель дала такой прогноз именно в эту дату? | Проверка логики перед решением |
| Объяснение | SHAP и permutation | Что вообще важно для модели, и согласуются ли два способа оценки? | Понимание драйверов |
| Объяснение | PDP/ICE | Как прогноз изменится при изменении признака? | Оценка чувствительности |
| Объяснение | Тепловая карта и корреляции по годам | Устойчива ли логика модели во времени? | Доверие на смене режимов |
| Мониторинг | Скользящая MAE против порога | Модель ухудшилась? | Нужно ли переобучать |
| Мониторинг | Статус правила переобучения | Что система решила? | Запрос переобучения |
| Мониторинг | Таблица PSI/KS | Изменились ли входные данные? | Причина деградации |
| Мониторинг | Реестр и события | Какая версия работает, можно ли откатиться? | Управление версией |
| Мониторинг | Симуляция деградации | Сработает ли система при ухудшении? | Проверка защитного контура |
| Эксперименты | Таблица журнала | Какая конфигурация лучше и как её повторить? | Воспроизведение |
| Эксперименты | CV против отложенной выборки | Не переобучена ли модель на этапе разработки? | Доверие к метрикам |
| Эксперименты | Сходимость Optuna | Достаточно ли бюджета подбора? | Планирование подбора |
| Данные | Статус и таблица контроля качества | Корректны ли данные? | Доверие к витрине |
| Данные | Журнал загрузок | Какие источники сработали? | Диагностика |
| Данные | Отчёт об утечке | Не подглядывает ли модель в будущее? | Доверие к модели |

Удалено при проектировании: свечной график цены и лента новостей, так как ни на один вопрос о завтрашнем объёме и риске они не отвечают.
