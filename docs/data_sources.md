## Что случилось с GDELT и почему история взята из Hacker News

Постановка предполагала историю новостей из GDELT. Проверка показала другое:

- За время разработки к API было сделано более 20 запросов с паузами от 7 секунд до 2 минут. Успешных ответов было только 2 (окна в 1 и 7 суток, простой запрос `bitcoin`), остальные получили HTTP 429 с сообщением о лимите частоты.
- При длительном запуске (30 минут, интервал около 2 минут) не прошло ни одного запроса.
- Один запрос занимает 12-22 секунды, поэтому даже без 429 полная история заняла бы часы; при фактической доле отказов она недостижима за рабочий день.

Статические файлы GKG GDELT доступны, но это 30-46 МБ в сжатом виде на сутки (около 80 ГБ за период), и в них нет заголовков, только темы и URL. Для студенческого прототипа на ноутбуке это неоправданно.

Обойти лимит (смена IP, распараллеливание) я не пытался: сообщение API прямо просит не превышать частоту.

Решение:

- Историю заголовков даёт **Hacker News через Algolia API**: публичный, без ключа, глубина больше нужного периода. Поля автора не читаются и не сохраняются.
- **GDELT остаётся в конвейере** как отдельный источник с бережным бюджетом (не более 3 попыток за запуск, watermark двигается только после успеха). При 429 запуск фиксирует статус `partial` и продолжается. Коллектор поддерживает загрузку свежих окон вперёд и истории назад, поэтому при снятии ограничения ничего менять не придётся.
- **RSS** накапливает свежие новости с начала сбора.

Ограничения Hacker News как источника, которые нужно учитывать при чтении результатов:

- Это техническое сообщество, а не новостная лента: выборка отражает интерес разработчиков к теме и смещена относительно настроений рынка.
- Заголовков немного: порядка нескольких десятков в день суммарно по всем запросам.

## Журнал сделок aggTrades

Запасной вариант из постановки. Для пяти инструментов за 5,8 года это сотни гигабайт (суточный файл BTC — десятки мегабайт). Текстовый источник из Hacker News оказался доступен, поэтому журнал сделок не загружался.

## Правила работы с временем

- Все метки времени хранятся в UTC без часового пояса.
- Берутся только закрытые свечи: `close_time < now`.
- Строка витрины за дату D содержит только данные, известные к концу суток D UTC, а цели относятся к D+1.
- Индекс страха за дату D публикуется в начале суток D и известен к концу D.
- Дата новости — сутки её публикации (`seen_at`).

## Лимиты и нагрузка

- Binance: 1000 свечей на запрос, вес запроса 2, пауза 0,15 с.
- Hacker News: пауза 0,25 с, окно 30 суток.
- GDELT: не более 3 запросов за запуск, пауза 8 с, таймаут 120 с.
- Все запросы проходят через `cryptocast/ingest/http_client.py`: таймауты, повторы с экспоненциальной задержкой, обработка 429 и Retry-After.
